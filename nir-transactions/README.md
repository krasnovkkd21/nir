# Выявление мошеннических банковских операций

Программа оценивает очередную покупку или перевод с учётом предшествующей истории клиента. В проекте сохранена рабочая модель `pooled_full188` с двумя обученными компонентами. Transformer формирует 33 признака последовательности. XGBoost объединяет их со 155 характеристиками платежа и поведения клиента и рассчитывает оценку риска. Два порога определяют рекомендуемое действие.

## Быстрый запуск

Проверено на Python 3.12 и CPU. Из каталога проекта выполните следующие команды.

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python predict.py examples/features.parquet outputs/example.parquet
python -c "import pandas as pd; print(pd.read_parquet('outputs/example.parquet').to_string(index=False))"
```

В примере три синтетические операции с заранее рассчитанными признаками. Ожидаемый результат в порядке строк — `allow` (пропустить), `require_confirmation` (запросить подтверждение) и `manual_review` (направить на ручную проверку). Столбец `risk_score` содержит оценку для ранжирования. Решение о фактическом проведении или блокировке платежа принимает внешняя система.

## Запуск на новых операциях

```sh
python features.py generate --output-dir data/demo --clients 30 --seed 42
python features.py build --data-dir data/demo --output-dir data/demo-features --period 4
python predict.py data/demo-features outputs/demo.parquet
```

Первая команда создаёт синтетические покупки в терминалах и интернете, оплату по QR, переводы и возвраты. В набор входят транзакции в рублях, журналы сессий и устройств, сведения о торговых точках и получателях. Разметка мошенничества и принадлежности к эпизоду хранится отдельно. Заданный seed позволяет повторить пример.

Вторая команда рассчитывает признаки для выбранного периода. При этом сохраняется доступ к более ранним операциям клиента. Для расчёта используются наблюдаемые на момент платежа данные. Чтобы получить признаки для всех периодов, опустите `--period 4`. Для нового запуска генератора и расчёта признаков укажите свободные каталоги. Третья команда возвращает идентификатор операции, оценку риска и рекомендуемое действие.

## Обучение и проверка

Transformer обучался по разметке операций. Из 29 эпох выбраны веса 23-й эпохи по средней точности ранжирования на валидации. Эти веса использовались для подготовки входа XGBoost. Классификатор обучен на 2 600 229 операциях 30 000 клиентов, среди которых 8 653 операции размечены как мошеннические. Выбрано 250 деревьев. Порядок признаков и пороги сохранены в `models/policy.json`.

На двух независимых синтетических группах из 12 000 клиентов рабочая модель обработала 1 043 937 операций.

| Показатель | Результат |
| --- | --- |
| Обнаруженные мошеннические операции | 2 512 из 3 230 (77,77 %) |
| Обнаруженные первые операции эпизодов | 226 из 518 (43,63 %) |
| Законные операции, направленные на проверку | 3 512 из 1 040 707 (0,3375 %) |
| Доля мошеннических среди направленных на проверку | 2 512 из 6 024 (41,70 %) |

В этих результатах обнаружением считается направление операции на подтверждение или ручную проверку. Влияние подтверждения на финансовые потери в эксперименте не измерялось.

## Файлы

- `models/encoder/` — веса Transformer, параметры нормализации в контрольной точке и описание входных полей.
- `models/pooled_full188.ubj`, `models/policy.json` — веса XGBoost, схема входа и пороги.
- `pipeline/`, `features.py` — генератор, расчёт признаков и запуск кодировщика.
- `predict.py` — расчёт риска и выбор действия.
- `training/` — повторное обучение Transformer и XGBoost. Веса нового эксперимента записываются в отдельные каталоги. Порядок запуска описан в [инструкции по обучению](training/README.md).
- `examples/features.parquet` — три контрольные строки для проверки установки.
